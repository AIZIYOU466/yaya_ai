# YAYai 真机回归清单（ROADMAP 任务 36）

首个正式版 `v1.0.0` 发布前的真机验收工具。三条主线逐项操作、逐项打勾；全部通过即可按 R17 打 Tag 发版。

- 包标识：`com.yaya.ai`；`versionName 1.0.0` / `versionCode 1`；数据库 `DB_VERSION 4`
- 建议机型：arm64 Android 真机（侧载 `armsolo` 或 `universal` 包）
- 结论记录：每条主线末尾填「通过 / 不通过 + 现象」；不通过则修 `main` 后重测、重新打 Tag（递增 patch，不重写已推送 Tag）

---

## 主线 A：AI 对话

前置：至少配置一个云端模型提供商（设置 → 模型提供商 → 添加，填 Base URL / API Key，拉取或手动添加模型）。

- [ ] **A1 基本对话**：发送「你好」，收到流式回复，回复显示 token 明细与耗时
  - 预期：流式输出不卡顿，气泡下展示 prompt/completion 拆分与会话累计
- [ ] **A2 工具调用**：发送「列出工作区根目录的文件」，模型调用 `file_list` 并回填结果
  - 预期：工具结果回填后模型继续作答；BUILD 模式下只读工具不弹确认
- [ ] **A3 运行模式**
  - [ ] BUILD：发送「在工作区创建 test.txt 并写入 hello」，写操作前弹授权框（显示工具、参数、撤销成本），允许后成功创建
  - [ ] PLAN：同一请求被拦截，返回明确拒绝原因（不是静默失败）
  - [ ] AUTO：同一请求不再弹确认，直接执行
- [ ] **A4 多模型切换**：对话页顶部模型按钮切换另一提供商/模型，新回复来自切换后的模型
- [ ] **A5 多模态**：点输入框图片按钮，相册多选（≤4 张）发送，消息气泡显示缩略图；助手 Markdown 图片可内联展示、点击全屏缩放
  - 预期：模型未标注 `image` 能力时按钮给提示且不发送
- [ ] **A6 子代理**：发送「用 explore 子代理看一下工作区有哪些文件」，任务卡显示子代理状态 chip，点开可看子任务与结果摘要
  - 预期：主循环等本批结果后继续；并行上限在设置 → 子代理配置
- [ ] **A7 会话管理**：新建 / 切换 / 重命名 / 删除会话；删除后级联清理消息
- [ ] **A8 任务队列与断点续跑**：AI 工作中继续发消息进入队列；点停止 = 挂起，点继续从断点续跑（已执行工具不重复）
- [ ] **A9 斜杠命令**：发送 `/status`，返回当前模型、模式、token 累计与队列长度
- [ ] **A10 备份与恢复**：抽屉 → 备份，加密导出 `.yayabak`；换新设备导入并用同一密码恢复（配置 + 工作区 + 技能；不含会话/记忆库）

## 主线 B：终端容器

入口：抽屉 → 终端。镜像管理在**终端页顶部「Linux 环境（镜像）」条**，容器由**右上角 ▶** 启动。

- [ ] **B1 安装镜像**：顶部镜像条选择并安装内置 Alpine rootfs（首次自动下载），安装完成后状态显示已就绪
- [ ] **B2 启动容器**：点右上角 ▶，状态变为运行中；未启动时输入区提示「点右上角 ▶ 启动 Linux 环境」
- [ ] **B3 命令执行**：输入 `uname -a`，逐行回显输出与容器内核信息
- [ ] **B4 多标签**：新建 / 关闭 / 切换最多 5 个标签，各自保留回滚缓冲与命令历史
- [ ] **B5 辅助按键**：Esc / Tab / Ctrl-C / ←→ / ↑↓ / 常用符号可用；Ctrl-C 能中断长命令
- [ ] **B6 AI 标签**：在对话页让 AI 执行一条终端命令（如「在终端里运行 `echo hi`」），终端只读「AI」标签出现该命令及输出与退出码
- [ ] **B7 工作区一致性**：对话中让 AI 用 `file_write` 写文件，终端里 `ls /workspace` 能看到同一文件（工作区 bind）
- [ ] **B8 Git**：容器内 `apk add git` 后，文件页右上角 Git 图标可用（状态/暂存/提交）；未装 git 时页面给出提示

## 主线 C：MCP / 端侧模型（二选一即可，或都测）

### C-MCP

入口：抽屉 → MCP。

- [ ] **C1 添加服务器**：点「添加第一个服务器」/新增，填名称（不含 `__`）、启动命令（如 `npx`）、启动参数；启用后保存
- [ ] **C2 工具暴露**：对话中请求该服务器某项能力，模型调用 `mcp__<server>__<tool>` 并回填结果
- [ ] **C3 不可用降级**：故意填错启动命令后请求，Agent 明确提示 MCP 不可用并退回内置工具（不静默）
- [ ] **C4 删除服务器**：删除后其工具不再暴露

结论：______

### C-端侧模型（可选，默认 STUB）

入口：设置 → 端侧模型。

- [ ] **C5 导入模型**：从系统文件选择器导入 `.gguf`，复制进应用私有目录；卡片显示体积，可删除、可选中
- [ ] **C6 STUB 明示**：未启用 llama.cpp 全量构建时，界面明确显示端侧为 STUB（不可推理），不误导
  - 注：端侧真实推理（llama.cpp 全量编译 + function-calling）属任务 31 剩余，**不是本次发版硬门槛**

## 发布步骤（R17）

前置：GitHub 仓库 Settings → Secrets 已配置签名密钥，否则 CI 会退回 debug 签名（不可作为正式版发布）。

- Secrets 清单：`ANDROID_KEYSTORE_B64`（keystore 的 base64）、`ANDROID_KEYSTORE_PASSWORD`、`ANDROID_KEY_ALIAS`（默认 `yaya`）、`ANDROID_KEY_PASSWORD`
- [ ] 三条主线全部勾选通过
- [ ] `main` 上 `cargo test` / JNI check 通过（可与 CI 并行）
- [ ] 打 `v1.0.0` Tag 并推送 → CI（`.github/workflows/android-release.yml`）构建签名 Release APK
- [ ] 从 CI 产物下载 APK，在真机安装（与后续升级签名一致）
- [ ] 发布后不再重写已推送 Tag；`AgentDatabase.DB_VERSION`（当前 4）随本版冻结，已发布版本号不复用

## 已知注意点

- 终端容器为**单实例单进程**，多标签是独立窗口、命令串行执行（非并行会话）。
- 远程 SSH 后端（任务 35）与本地 proot 互斥：启用后 `terminal_exec` 与文件工具走远端 SFTP，终端页 / Git 页仍为本地 proot。
- Compose UI 侧此前多为容器内 UNVERIFIED，本清单即其首次真机确认。
